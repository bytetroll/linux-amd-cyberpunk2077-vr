# Porting notes

## Implemented corrections

- **Layer allocation:** the tested Proton OpenXR conversion used one element size for heterogeneous pointer arrays. The supplied source patch sizes each non-null element separately. The separately guarded binary workaround is narrower and applies only to the verified projection-first Win64 case.
- **Eye geometry:** the engine's resize hook must change the requested resolution without pretending that the active buffers already match it. The trampoline also preserves the original width/height branch behavior. This avoids mismatched MAIN/VRCAM image dimensions and severe eye-to-eye crop differences.
- **Native return alignment:** `RED4ext::Quaternion` requests 16-byte alignment, while the tested CET scratch return allocator can supply 8-byte-aligned storage on Windows. An optimized aligned store faulted in `VRBoneModelRot`. All eight native quaternion readers now write the same four floats using alignment-safe scalar stores. The regression fixture reproduces the old fault and checks all readers without running the game.
- **Grenade validation:** unavailable bone positions are non-null structs with `w=0`. Held-item transforms reject those values, non-finite coordinates and unusable quaternion norms. Valid pose arithmetic is preserved.
- **Menu input:** XInput import patching starts before the delayed engine-hook pass. The native pointer holds the mouse button for trigger-held inventory dragging and releases it at the current pointer location. Tracking, focus, target or menu loss releases an owned press and requires trigger release before reuse. Disabling the pointer restores trigger-as-gamepad-A confirmation. Existing face buttons and physical gamepad input remain available.
- **Body recovery:** a brief same-origin tracking interruption no longer discards an already-active roomscale catch-up. Recovery pauses velocity and accepts no unknown travel. Long gaps, explicit suspension, recentering and tracking discontinuities still cancel the request.
- **Runtime queue:** on Wine/SteamVR, the OpenXR session uses a separate D3D12 DIRECT queue. Rendering and capture remain on the game queue. Successful image waits signal from the runtime queue to the game queue; releases wait on the exact game-copy fence in the reverse direction. HUD preparation precedes eye release, and submission failures stop further image handoffs. Headset performance validation is pending.
- **Index input:** D-pad Up toggles scanning by default through the existing left-stick-click/right-stick direction shortcut. The VR Up bit is consumed before native input merge, leaving physical gamepad input intact. D-pad mode disables the optional grip/ear scanner gestures so grips remain available for items. Scanner navigation emits one step per left-stick deflection. The native-menu pointer uses the submitted quad geometry; pressing the left oval touchpad opens the equipment hub without invoking the map hold shortcut.
- **Movement heading:** HMD and controller movement directions use the projected forward vector consistently with body tracking. Quaternion normalization and a per-origin heading latch prevent pitch/roll contamination, torn quaternion reads and near-vertical heading jumps. The captured poses showed up to 4.65 degrees of error from the old equation; this does not establish the full cause of the reported sideways lock. Bounded `[moveheading]` diagnostics record raw input, output and body compensation for the next reproduction.
- **Manual reload and grenade release:** after magazine insertion, moving the same hand at least 8 cm relative to the weapon can hand the held squeeze to a valid slide target. The magazine remains locked against immediate removal. An unarmed grenade release is handled before new arming gestures; old arming timers and pose frames are cleared between grabs. An already armed grenade retains its throw-on-release behavior.
- **Belt reach:** target hysteresis checks the selected pouch's own distance even when another pouch becomes nearest. A grenade grip edge refreshes that hand's target immediately, so a stale cosmetic highlight cannot select a pouch the hand has already left.
- **Holster and carry:** clothing classification applies to drawing only. A held weapon can be put away at a body holster zone. Left-slot props are excluded, left weapons use the native transaction system, and carry cleanup prevents the same squeeze from recreating an externally holstered weapon.
- **Physical stance:** neck-pivot displacement is normalized to its neutral height before the ordinary crouch deadzone. The floor-reach threshold is unchanged. Bounded stance logs distinguish physical squat from the independently reported native locomotion state.
- **Finger articulation:** optional OpenXR hand joints supply individual phalanx bends on free hands. Retargeting replaces bind-pose flexion while preserving the other rotation components. Interaction-specific poses keep priority; inactive, unsupported and stale input preserves the existing animation.

## Open performance work

Earlier per-call measurements put roughly 86% of the slow sampled XR cycles inside the two eye swapchain releases plus the HUD release. The tested Proton D3D12 bridge drains its submission queue at release. The separate runtime queue still waits for image copies on the game queue; this dependency cannot be removed without risking incomplete images.

In the last 60 focused sampling windows of the October 19 run, the mod submitted about 40.9 frames/s and received 37.1 distinct captured frames/s. Capture age averaged 24.4 ms; HUD release averaged 5.48 ms, both eye releases combined 3.77 ms, and `xrEndFrame` 6.57 ms. These are CPU wall timings and different gameplay from the earlier capture, not a controlled GPU or FPS benchmark. The log does not establish compositor reprojection/drop rates. The input/stance candidate makes no additional performance claim; an instrumented headset run remains necessary.

Moving the image-copy commands themselves to a dedicated queue would also require exact capture-producer fences and retention of capture-buffer read leases until the consumer finishes. The current change keeps those readers and writers on the game queue and isolates only the runtime queue. It retains the runtime's drain and explicitly transfers image availability in both directions. The game submission mutex is not held across runtime release calls.

Remaining symptoms include SteamVR fade/void on rapid movement and occasional body desynchronization. Stale body tracking can coincide with long submission cycles, but a fixed head/body transform defect has not been demonstrated.

## Publication scope

This repository starts with a curated source snapshot. It contains no private development history, local SDK downloads, build outputs, player configuration dumps, crash logs, saves, screenshots or extracted game archives. Required dependencies are obtained from their public upstream sources. See the build guide and third-party notices for the components intentionally supplied separately.
